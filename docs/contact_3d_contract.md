# 3D接触採否・打球生成の仕様 v1

## 適用範囲

同じ3D接触イベントからEV・HLA・VLAを生成するための仕様と、診断用の参照実装。
`tools/diagnostics/contact_3d.py`の`ContactGeometry`と`solve_contact()`を、
`rotating_bat_probe.py`が使用する。本体Rustの打撃判定は今回変更しない。

保存状態v1、診断probe v2、この接触仕様v1はそれぞれ別のバージョン。
保存済み状態は近似入力であり、今回の整理で実測スイングへ置き換わるわけではない。
旧ContactTypeは比較用ラベルとして保持する。新しい品質閾値を決めて本体へ適用する段階は別とする。

## 座標・入力の責任範囲

世界Xは球場の右、Yは本塁から投手・外野方向、Zは上。時間0は投球リリース。
バット軸aは基準打点から先端側の単位ベクトル、法線nはバットから球中心へ向く。
すべての接触位置・速度・法線は同じ接触時刻の世界座標とする。

| 入力 | 意味・今回の近似 | 適用する場所 |
|---|---|---|
| ball_position / velocity | 本塁面での推定位置・速度。局所探索では等速 | 球の軌道 |
| aim_error | 認識・実行誤差の世界X/Z代理値、Y=0 | 理想基準打点をball_position−aim_errorとする |
| bat_axis | 実行バット角と打席符号から作る単位軸 | 基準姿勢。打席符号の再適用はしない |
| attack_angle / bat_speed | 基準打点速度v=(0,B cosα,B sinα) | 軌道の基準速度 |
| timing_offset | 秒単位の遅れ。正が遅い | バット軌道をt−Δで評価する |
| lever / half_length | 回転中心までの距離／基準打点からの接触区間半長 | 軌道・形状の仮定 |
| restitution / effective_mass | 法線方向の衝突係数／有効質量 | 接触後の力積計算 |

基準打点は幾何学上の原点であり、反発が最大になる実測スイートスポットを同定した位置ではない。
回転中心、基準打点、接触区間を分ける。Lをバット全長や接触区間長として兼用しない。
狙い誤差の分布を変える場合は、保存状態のsource/versionを更新して混在を区別する。

## 接触採否から打球までの順序

1. 見送り判断の後、スイングの入力を生成する。旧接触採否に関係なく探索対象にする。
2. その入力で球とバットの軌道を定義し、同じ時計で最初の接触候補を探索する。
3. 探索結果をcontact / no_contact / overlap_at_start / unresolvedに分ける。
4. contactの場合に、その時刻の法線n、球速度v_ball、バット接触点速度v_batを確定する。
5. 接近している場合だけ法線力積を計算し、衝突後の球速度ベクトルv_outを得る。
6. **v_outの長さと向きからEV・HLA・VLAをすべて計算する。**
7. その打球を軌道計算へ渡し、ファウル・本塁打・守備結果などを決める。

今回の実装は診断内の1～6に対応する。7への本体接続は行っていない。
no_contactは指定した形状・時間窓内の結果。unresolvedを空振りに読み替えない。
開始時近接は区間内の初回接触が未確定なので、打球速度を生成しない。
空間許容差内の近接はcontact候補に含む。探索の詳細は[回転診断仕様](rotating_bat_probe.md)を参照。

## 重複させない変換

| 旧処理 | 3D候補での扱い |
|---|---|
| Xへ0.75×B×Δを加算 | 比較用legacy値のみ。幾何学入力に加算しない |
| timingから旧face角を作りHLAへ加算 | 位相で回転した姿勢に含める。出力HLAに加算しない |
| attack angleをVLAへ加算 | 打点速度と軌道へ反映する。出力VLAに加算しない |
| 旧X/Zから接触法線やEV減衰を生成 | 今回の接触位置・法線・速度から計算する |
| 旧ContactTypeの乱数降格 | 比較ラベルとして保持。3Dの衝突式には渡さない |
| approach/pullの乱数角 | 現在の候補は未導入。導入時はスイングの基準姿勢など入力側へ定義する |

旧コードは`batting_resolver.rs`のevaluate_swing_contact_with_timing_scale、
calculate_launch_angles、EV計算に分散している。診断参照実装には旧分類・旧タイミング項を受け取る引数がない。
保存状態に比較用legacy値が同居していても、これらを変えて接触結果が変わらないことをテストする。
本体移行時は旧乱数消費の変更も明示し、同じseedの試合結果だけで効果を断定しない。

## 接触イベントと衝突式

`ContactGeometry`はリリースからの接触時刻、単位軸、単位法線、球中心の軸方向座標、
有限線分上の最近点の軸座標、接触区間半長、side/capを持つ。
非有限値・負の時刻・非単位ベクトル・区間と最近点の矛盾・側面法線の直交性などを検証する。
この検証は探索器が返す位置そのものの妥当性を独立に証明するものではない。

```text
u = v_ball - v_bat
u_n = dot(u,n)
delta_v = max(0, -(1+e)*u_n / (1 + m_ball/M_effective))
v_out = v_ball + delta_v*n
normal_impulse = m_ball*delta_v
```

u_n<0が接近。非接近の場合はnon_approachingとして、打撃用EV/HLA/VLAをNULLにする。
法線方向だけの摩擦なし衝突。m_ball=0.145kg、既定e=0.5、M_effective=0.6kg。
有限有効質量の応答を仮定した反発則残差と、球の接線方向速度変化の残差を記録する。
バットの慣性テンソルや衝突後の回転運動を解いたモデルではない。
接触点の回転速度は使用するが、現在のM_effectiveは軸位置によらず一定。

```text
EV  = |v_out|
HLA = degrees(atan2(v_out.x, v_out.y))
VLA = degrees(atan2(v_out.z, hypot(v_out.x,v_out.y)))
```

水平速度0ではHLAは未定義、球速度0では両角度とも未定義。
HLAの±45°は発射時のファウル方向の区分であり、軌道・風・壁・捕球を含む最終結果とは区別する。

## 品質は幾何学と速度で記述する

Solid/Weak/Marginalという新しい閾値を先に割り当てず、次の連続量で接触を整理する。

| 次元 | 定義 | 集計帯 |
|---|---|---|
| axial_fraction | 有限線分上の最近点の絶対軸位置／半長 | <0.25、0.25..<0.5、0.5..<0.75、0.75..1、cap別 |
| normal_speed_fraction | max(0,−u_n)/|u| | <0.5、0.5..<0.8、0.8..<0.95、0.95以上 |
| normal_elevation_deg | asin(n.z)の度数 | −30未満、−30..−10、−10..10、10..30、30以上 |
| bat_point_speed_ms | 接触点速度の大きさ | 25未満、25..30、30..35、35..40、40以上m/s |

各帯は診断用区分で、強打・弱打を決めるゲームルールではない。
4次元はそれぞれ独立に集計する。同じ球が各次元に1回ずつ現れるので、次元をまたいで合算しない。
旧分類別の行に加えてall/allの全体行を持ち、全体行と旧分類行も合算しない。
各行のcontactsは正の力積を受けた接触数。角度の割合はdefined_*_contactsが分母。

浅い接触でも投球が元々持つ速度が残るため、EVが高いことだけで強いフェア打球と判定しない。
法線方向の相対速度比・発射方向・EVを併せて読む。
軸位置の大きい球で接触点速度とEVが増える場合は、一定有効質量という仮定も含めて検討する。
旧Weak/MarginalのEVを再現するために旧分類別の減衰係数を追加しない。

## 診断の実行

新しい`rotating_bat_probe.py`は従来の出力に品質記述の列と次の集計を追加する。
入力ボール速度・衝突後速度のXYZも直接保存する（probe v2）。同じ式への整理なので、従来の
正常な接触のEV/HLA/VLAと探索採否は維持する。

| ファイル | 内容 |
|---|---|
| contact_3d_status.csv | 条件×旧分類×旧miss原因ごとの衝突成功・非接近・無効・探索未解決など |
| contact_3d_quality.csv | 条件×品質次元×帯ごとの件数、EV/VLA・発射方向率と入力指標 |

既存のrotating_contacts.csvとrotating_metadata.json（probe v1またはv2）だけでも、DBなしで実行できる。

```sh
python3 tools/diagnostics/contact_3d_quality_probe.py --contacts-csv "/path/to/rotating_contacts.csv" --metadata-json "/path/to/rotating_metadata.json" --output-dir ../saberbb_contact_quality
```

出力先は未作成のディレクトリを指定する。元CSV・JSONは書き換えない。
追加でcoverage、checks、exclusions、metadataを出力する。
probe v1は入力球速度を持たないので、v_out−delta_v*nから再構成する。
これは過去の計算結果の整合性検証であり、投球速度の独立な測定・検証ではない。
v1の非接近記録などで逆算に必要な値がない場合は理由を残して除外する。
v2は直接記録した球速度を必須とする。
再計算と記録値の誤差が1e-7（速度はm/s、角度は度）を超えた行は、品質集計から除外して明示する。
不正な法線・形状メタデータ不一致・欠損も同様。重複キーと未対応メタデータは処理を停止する。

## 本体適用前の未決事項

- 狙い・実行誤差を世界X/Zの位置差へ置く代理モデルの妥当性と分布。
- 回転中心・姿勢・回転半径・探索時間、投球速度近似の妥当性。
- 接触点・反発・有効質量・摩擦・スピンのモデル化。
- 打者能力をこれらの入力にどう反映するか、品質ラベルをUI・統計でどう扱うか。

仕様整理と代数的な整合性の検証を、現実の打率・Contact率の妥当性検証と区別する。
本体へ適用する場合は、3Dの接触結果を先に確定し、その同じ接触状態から打球生成へ接続する。

## 実行角度誤差と打点位置の一体化

[診断入力v2](execution_frame_v2.md)では、理想・実行の支点を共有し、角度誤差で打点位置・軸・
支点からの相対速度を一緒に変える。既存の保存状態v1から導出した比較用入力で、DB更新は行わない。
打点を狙い位置へ再配置する従来条件との同一球比較を行う。
