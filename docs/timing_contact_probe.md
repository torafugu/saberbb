# タイミング由来の位置ずれの感度診断

既存DBには `migrations/upgrades/add_contact_bat_angle.sql` を1回実行し、
改修後のコードで新しい試合を生成する。新規DBは最新DDLを使う。
この変更は接触判定時の `actual_bat_angle_deg` を保存するだけで、乱数呼び出し・接触判定・
打球角度・EV・試合結果は変えない。見送りはNULL。旧データもNULLのまま。
符号を失ったlength/thicknessからバット角を推測して埋め戻さない。

`sql/diagnostics/timing_contact_probe.sql` の4本に `:first_game_id` / `:last_game_id` を指定する。
SQLiteのSIN/COS/ACOSを使用する。同じSQLを再実行しても同じ結果になる。

各スイングから4条件（1.0/0.75/0.5/0.0）を作り、次を計算する。

```
probe_x = contact_offset_x_m + (timing_scale - 1) * timing_impact_x_m
probe_z = contact_offset_z_m
length = abs(probe_x*cos(angle) + probe_z*sin(angle))
thickness = abs(-probe_x*sin(angle) + probe_z*cos(angle))
```

固定するのは実際のバット角、空間誤差、スイング実行誤差、接触限界（長さ0.16m・厚み0.070m）。
厳密な超過 `>` を使う。角度変化やタイミング予測を再計算せず、横方向に加算する
タイミング由来の位置ずれだけを縮小する。元のタイミング帯は固定した層別軸として使う。
0%は理想的な打者や新しい物理モデルを意味せず、その項を除いた比較条件。

1. 記録の充足と100%版の再現性。まずmissing_input_swingsとbaseline_mismatchesを確認する。
   baseline_mismatchesは保存済みの長さ・厚み（許容誤差1e-9m）と接触／空振りの両方を検査する。
   非ゼロなら係数の解釈を進めず、コード版・記録・閾値を確認する。
2. 同一スイング群の接触可能率と、接触へ変わった数／逆に空振りへ変わった数。
3. 2ストライク・ゾーン内外・元のタイミング帯・固定バット角帯ごとの比較。
4. 現行分類から各条件への遷移件数。

入力が欠けた球は4条件すべてから除外し、条件ごとに比較対象が変わらないようにする。
カウント・コース・元タイミングだけが欠ける場合はunknown層として残す。
割合の分母は比較可能な全スイングで、元々の接触も含む。

縮小によって空間誤差との打ち消しが弱まると、元の接触が空振りへ変わる場合もある。
接触率が単調増加するとは仮定しない。両方向の変化を見る。
接触可能率は幾何条件の成立率であり、Solid/Weak/Marginalの再抽選、EV/HLA/VLA、
ファウル、安打、総K率までは再シミュレーションしない。
75%・50%は原因調査用で、採用すべき補正値を決めたものではない。
まず1〜3本目を比較し、必要に応じて4本目でどの空振り群が残るかを確認する。
