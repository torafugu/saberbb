# Batting Parameters

Batting-related parameters are defined in `src/domain/shared/player.rs`, generated by `src/domain/player_factory.rs`, loaded through `src/domain/player_service.rs`, persisted by `src/repositories/player_repository.rs`, and consumed by `src/domain/resolver/batting_resolver.rs`.

Batting is generated and persisted for non-primary-pitcher players. Primary pitchers currently have `offense_skills.batter = None`.

## BatterInfo

`BatterInfo` stores batting-side, approach, zone profile, swing, contact, and consistency attributes.

| Parameter | Type | Stored in DB | Description |
| --- | --- | --- | --- |
| `batting_side` | `RL` | `batter_info.batting_side` | Batting side. Values: `Right`, `Left`. |
| `batter_type` | `BatterType` | `batter_info.batter_type` | Plate-approach archetype used by `sample_plate_approach()`. |
| `zone_aptitude` | `ZoneAptitude` | `batter_info.zone_aptitude` | Hot/cold-zone profile used by `zone_modifier()`. |
| `hot_zone_scale` | `f64` | `batter_info.hot_zone_scale` | Strength multiplier for the zone-aptitude modifier. |
| `batting_eye` | `f64` | `batter_info.batting_eye` | Pitch-recognition skill used by pitch timing perception. |
| `swing_speed` | `f64` | `batter_info.swing_speed` | Bat speed used for timing impact, exit velocity, and collision spin. |
| `swing_power` | `f64` | `batter_info.swing_power` | Power value used to scale swing contribution to exit velocity. |
| `attack_angle` | `f64` | `batter_info.attack_angle` | Baseline attack angle in degrees. |
| `bat_control` | `f64` | `batter_info.bat_control` | Contact-control skill used to adapt to pitch offset and reduce swing-angle error. |
| `consistency` | `f64` | `batter_info.consistency` | Batter-level consistency value. It is generated and persisted but is not currently used by batting resolution. |

## Batter Types

`BatterType` controls plate approach and attack-angle adjustment.

| Value | Meaning | Attack-angle modifier |
| --- | --- | --- |
| `AggressiveFreeSwinger` | Aggressive, feel-driven hitter. | `10.0` |
| `ClassicAnalyst` | Cautious, analytical hitter. | `2.0` |
| `GameManager` | Hitter that adapts to the game situation. | `3.0` |
| `ClutchHunter` | High-risk, power-oriented hitter. | `0.0` |

`default_plate_approach(batter_type)` currently returns only `PlateApproach::Aggressive` entries for every batter type, with different weights.

## Zone Aptitude

`ZoneAptitude` controls the Gaussian peaks used by `BatterInfo::zone_modifier(location)`.

| Value | Behavior |
| --- | --- |
| `Balanced` | One positive peak at zone center. |
| `InsideDominant` | Positive center peak plus an inside-zone peak. |
| `OutsideDominant` | Positive center peak plus an outside-zone peak. |
| `LowBaller` | Positive low-zone peak and negative high-zone penalty. |
| `HighBaller` | Positive high-zone peak and negative low-zone penalty. |
| `DiagonalCross` | Positive diagonal peaks with opposite diagonal penalties. |

`zone_modifier(location)` sums all matching Gaussian peaks and multiplies the result by `1.0 + hot_zone_scale`.

## Persistence

Batting data is saved as part of `SqlPlayerRepository::insert_player()`.

| Table | Purpose |
| --- | --- |
| `batter_info` | One batting row per non-primary-pitcher player. Primary key: `player_id`. |

`GameRepository::load_batter()` loads batter rows with batting side, batter type, zone aptitude, hot-zone scale, batting eye, swing speed, swing power, attack angle, bat control, and consistency.

## Batting Factor

`calculate_batting_factor(pitcher, batter, actual_pitch_type, expected_pitch_type, actual_location, expected_location)` compares the real pitch to the batter's expectation.

| Component | Source |
| --- | --- |
| `distance_from_zone_edge` | `actual_location.distance_from_zone_edge()`. |
| `zone_similarity` | Similarity between `actual_location.target_zone()` and `expected_location.target_zone()`. |
| `pitch_similarity` | Difference between actual and expected pitch-skill spin rate and spin angle. |
| `zone_aptitude` | `batter.zone_modifier(actual_location)`. |
| `total_modifier` | Average of `1.0 - zone_aptitude`, `1.0 - zone_similarity`, and `1.0 - pitch_similarity`. |

Zone similarity values:

| Case | Value |
| --- | --- |
| Actual and expected are both `Center` | `0.3` |
| Actual is `Center`, expected is not `Center` | `0.1` |
| Same target-zone bucket | `0.2` |
| Opposite target-zone bucket | `-0.2` |
| Same height or same course | `0.05` |

Pitch similarity is clamped to `-0.2..0.2`.

## Swing Decision

`calculate_swing_factor(approach, count_status, pitch_type, batting_factor)` combines count, approach, pitch type, zone, and pitch-read factors.

| Input | Behavior |
| --- | --- |
| `CountStatus::prob()` | Count-dependent swing tendency. Three-ball counts are most take-heavy; two-strike counts are more swing-heavy. |
| `PlateApproach::prob()` | Added only before two strikes. `Aggressive = 0.2`, `Patient = -0.1`, `Take = -5.0`. |
| Pitch type | `FourSeamFastball` adds `0.1`; other pitch types add `-0.05`. |
| Batting factor | Adds distance from zone edge, zone similarity, pitch similarity, and zone aptitude. |

`select_swing_execution(rng, swing_factor)` swings when `rng.random() < sigmoid(swing_factor)`, otherwise takes.

## Contact Adjustment

`adapt_to_pitch(offset, bat_control, batting_factor)` scales pitch displacement before contact evaluation.

| Output | Formula |
| --- | --- |
| `total_modifier` | `((sigmoid(bat_control) + batting_factor.total_modifier) / 2.0).clamp(0.1, 1.2)` |
| `horizontal_offset_m` | `offset.horizontal_offset_m * total_modifier` |
| `vertical_offset_m` | `offset.vertical_offset_m * total_modifier` |
| `timing_offset_sec` | `offset.timing_offset_sec * total_modifier` |

`calculate_swing_execution_error(rng, batter, actual_location)` derives bat-angle and attack-angle error from pitch location, zone aptitude, and bat control.

| Value | Behavior |
| --- | --- |
| `ideal_bat_angle_deg` | `30.0 - location.y * 15.0`, clamped to `10.0..60.0`. |
| `actual_attack_angle_deg` | Dynamic attack angle plus the batter-type attack-angle modifier with 5% random variation. |
| `additional_x_m`, `additional_z_m` | Spatial swing error from angle error and `BAT_BARREL_LENGTH_M = 0.70`. |

## Contact Result

`evaluate_swing_contact(batter, offset, swing_execution_error)` projects timing and spatial error onto the bat.

| Output | Formula or threshold |
| --- | --- |
| `timing_impact_x_m` | `batter.swing_speed * offset.timing_offset_sec` |
| `offset_x_m` | Horizontal offset plus swing-execution X error and timing impact. |
| `offset_z_m` | Vertical offset plus swing-execution Z error. |
| `thickness_offset_m` | Offset projected onto the bat's thickness direction. |
| `length_offset_m` | Offset projected along the bat length. |

Contact type thresholds:

| Contact type | Condition |
| --- | --- |
| `SwungAndMiss` | `length_offset_m > 0.350` or `thickness_offset_m > 0.070`. |
| `FoulTip` | `thickness_offset_m > 0.055`. |
| `WeakContact` | `thickness_offset_m > 0.025`. |
| `SolidContact` | All offsets are inside the weak-contact threshold. |
| `Take` | Default value for no swing. |

## Launch Angles

`calculate_launch_angles(contact, batting_side)` converts contact offset into vertical and horizontal launch angles.

| Output | Formula or behavior |
| --- | --- |
| `vla_deg` | `contact.attack_angle_deg + asin(offset_z / 0.070) * 0.60`, with offset clamped to `-0.070..0.070`. |
| `hla_deg` | Face-angle component plus rebound component; sign is flipped for left-handed batters. |

Constants used by launch-angle calculation:

| Constant | Value | Meaning |
| --- | --- | --- |
| `EFFECTIVE_RADIUS_M` | `0.070` | Bat radius plus ball radius. |
| `SWING_ARM_RADIUS_M` | `1.10` | Swing rotation radius. |
| `VLA_REBOUND_FACTOR` | `0.60` | Vertical rebound deflection influence. |
| `HLA_FACE_FACTOR` | `0.85` | Horizontal face-angle influence. |
| `HLA_REBOUND_FACTOR` | `0.25` | Horizontal rebound influence. |

## Launch Speed

`calculate_launch_speed_with_power(contact_result, ball_speed, swing_speed, swing_power)` computes batted-ball exit velocity in meters per second.

| Step | Behavior |
| --- | --- |
| Max speed | `(0.18 * ball_speed) + (c_swing * swing_speed)`. |
| `c_swing` | `1.12 + 0.16 * effective_power`, where effective power comes from `sigmoid(swing_power)` and contact depth. |
| Thickness energy | Full inside `0.020m`; decays toward `0.0` by `0.070m`. Current code uses `length_offset_m` in the normalized decay term. |
| Length energy | `1.0 - (length_offset_m / 0.35)^2`, clamped to `0.0..1.0`. |

Contacting in front can add up to 5% swing transfer; contacting deep can remove up to 15%.

## Batted Ball Spin

`calculate_collision_spin(ball, swing_speed, contact)` computes collision spin and combines it with retained pitch spin.

| Component | Behavior |
| --- | --- |
| Contact distance | `sqrt(length_offset_m^2 + thickness_offset_m^2).min(1.0)`. |
| Collision spin angle | Opposite of the contact point angle, normalized to baseball spin notation. |
| Collision spin rate | `4000.0 * (swing_speed / 120.0) * contact_distance`. |
| Pitch-spin retention | `20%` of pitch spin is combined through vector addition. |

## Trajectory

`calculate_batted_ball(batter, ball, contact, stadium)` creates a `BattedBall` by calculating launch speed, launch angles, batted-ball spin, and then running `calculate_trajectory()`.

`calculate_trajectory()` simulates the batted ball in `0.01s` steps with gravity, air resistance, Magnus force, wind, ground bounces, and fence collisions.

| Constant | Value | Meaning |
| --- | --- | --- |
| `IMPACT_HEIGHT_M` | `0.90` | Initial batted-ball height. |
| `AIR_RESISTANCE_COEFF` | `0.0012` | Simplified air resistance coefficient. |
| `RESTITUTION_COEFF` | `0.45` | Ground bounce restitution. |
| `WALL_RESTITUTION` | `0.60` | Fence bounce restitution. |
| `GROUND_FRICTION` | `0.25` | Ground friction after bounce. |
| `MAGNUS_COEFF` | `0.0000336` | Magnus acceleration coefficient. |

Trajectory output includes launch speed, launch angle, spin rate, spin angle, final polar position, max height, total time, first bounce, optional fence impact, and outbound result.

| Outbound result | Behavior |
| --- | --- |
| `HomeRun` | Clears the fence in fair territory before bouncing. |
| `GroundRuleDouble` | Clears the fence after at least one bounce. |
| `Foul` | Clears the fence outside `FOUL_DEGREE = 45.0`. |
| `InField` | Default result when the ball remains playable in the field. |

## Game Flow

During an at-bat, `GameState` uses batting resolution in this order:

1. Create actual and expected pitches.
2. Calculate pitch movement and location bias.
3. Calculate `BattingFactor`.
4. Sample plate approach from the batter type.
5. Calculate swing factor and choose `Swing` or `Take`.
6. If taking, call the actual pitch location as ball, strike, hit by pitch, or wild pitch.
7. If swinging, adapt to the pitch, evaluate contact, and resolve swing-and-miss or batted-ball contact.
