# 後方打球とファウル側の場外判定の修正

## 変更

軌道計算の初速Y成分から`cos(HLA).abs()`の絶対値を除いた。
前方が正のYであり、絶対値90度を超えるHLAでは初速Yが負になる。
これまで157.557度の後方打球が約22.443度の前方打球へ折り返されていた。

ファウル側（現行の角度基準で絶対値45度以上）のフェンスに到達した場合は、
バウンド回数やフェンスの高さにかかわらず`OutboundResult::Foul`で終了する。
壁への衝突が空中かつフェンス以下の高さなら、衝突位置・時刻も記録する。
バックネット反射でフェア側へ戻ったり、バウンド後のファウル側場外打球が
`GroundRuleDouble`として二塁打になったりする経路を防ぐ。

フェア側のフェンス越えは従来どおり、ノーバウンドならHomeRun、
バウンド後ならGroundRuleDoubleとする。フェア側の壁の反射も維持する。
球場フェンスはバックネットまで閉じた形状であり、後方角度にも同じ探索を使う。

HLAの生成式、EV/VLA、接触判定、乱数処理、DBスキーマは変更しない。
これは軌道と場外判定の修正であり、野球規則上のフェア確定時点を追跡する
全面的な判定モデルや、バックネット到達前のファウルフライ捕球判定の追加ではない。
現行コードでは`outbound_result=Foul`が守備処理より先に解決される。

## 検証

Rust回帰テストを追加した。

- 正負の後方角度10ケースで初回バウンドと最終位置のYが負である。
- 左右のバックネット衝突はFoulで終了し、前方へ反射しない。
- 低いフェンスを使い、左右ファウル／中央フェアの空中・バウンド後の場外結果を検証する。
- 球場のフェンス距離を-180度から180度まで5度刻みで取得でき、真後ろは10mになる。

実行コマンド:

```sh
cargo test backward_
cargo test fence_clearance_checks_foul_direction_before_bounce_award
cargo test fence_distance_covers_backward_angles_and_backstop
```

## 試合生成後の比較

旧データを保持したまま、新しい試合を追加生成する。修正前と修正後の試合ID範囲を分ける。
既に共有された修正前の診断範囲は23266～23625だが、実際の保存範囲を確認して指定する。
この修正だけでは旧データの打球軌道や結果は変わらない。

1. `sql/diagnostics/foul_direction_outcomes.sql`を両範囲でそれぞれ実行する。
2. `sql/diagnostics/compare_contact_normal_hla.sql`で接触種別別のFoul率・EV/VLAを比較する。
3. `sql/diagnostics/compare_timing_position_trial.sql`でContact率・K率・接触全体のFoul率を比較する。

注目点:

- MarginalContactのbackward→fair→Out/DoublePlayがどれだけ減るか。
- final_directionがファウル側なのにGroundRuleDoubleとなる新規打球がゼロであること。
- ファウル側フェンス衝突がFoulとなり、前方への反射で結果が変わらないこと。
- 後方HLAが多いモデルでは、Foul率が上昇し得る。Contact率・K率・打席数も同時に評価する。

風・回転で方向が変わるため、「打ち出しファウル方向→非Foul結果」の全件ゼロは期待しない。
また、通常のファウルフライ捕球によるOutもFoul率には含まれない。
HLAモデルのバージョンは2のままなので、この変更の前後は試合ID範囲で区別する。
