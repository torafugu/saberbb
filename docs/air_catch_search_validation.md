# 空中探索修正と改修前後の比較

通常探索の空中区間を0.10秒開始の0.01秒刻みに変更する。
バウンド／フェンス接触後は、元の0.10 + n × 0.05秒のグリッドへ戻る。
時刻は加算の繰り返しではなく整数tickから算出する。着地時刻から0.05秒を加える方式ではない。
`evaluate_final_pickup` の探索間隔・遅延処理は変更しない。
候補の方向・距離フィルタ、要求余裕、エラー確率も維持する。
空中で新しく捕れる球が増えると担当・乱数消費の時点・以後の試合展開は変わり得る。

空中かどうかは、最初の有効なバウンド／フェンス接触／打球終了時刻までの差が
**1e-9秒より大きい**ことを要求する。通常・0.01秒診断・0.05秒診断は同じ関数を使う。
これは数値誤差対策であり、1サンプル（0.01秒）を削る補正ではない。
イベント直前の座標・高さの連続性は維持する。地面近くでも境界より明確に前なら
既存の高さ・時間・余裕条件で判定する。

DB列の追加はない。前回までの候補・診断用マイグレーションが適用済みなら追加移行は不要。
既存行は変更しない。以前の診断にあった境界直前のほぼゼロ高さの成立点は、改修後には除かれる。
したがって過去と新しい診断の差は探索刻みの修正だけでなく、境界ルールの統一も含む。
推定軌道自体の近似、野手の移動モデル、捕球可能と実際のアウトとの違いは引き続き残る。

## 手順

1. 改修前のコードで生成した試合IDの最小・最大を控える。旧データはそのまま保持する。
2. 改修後のコードで新しい試合を生成し、そのIDの最小・最大を控える。
3. `sql/diagnostics/compare_air_catch_search.sql` の5本のSQLを実行する。
   `:before_first_game_id` / `:before_last_game_id` / `:after_first_game_id` /
   `:after_last_game_id` を設定する。名前付きパラメータに対応しないツールなら数値に置き換える。
   両範囲は重複させず、各範囲内に異なる版の試合を混ぜない。

SQLは以下を出力する。

- 全投球に対する結果別件数・割合。
- フェア打球数・安打・単打数・本塁打を除くフェア打球安打率。
  最後の率は `H_without_HR / fair_balls_without_HR` で、このモデルの結果区分による集計。
- 選ばれた外野手の経路・捕球種別・結果。`seq = 1` だけを対象に送球後の重複を避ける。
- 1球単位の診断差。外野3行と0.01秒診断の記録が揃う球だけを集計する。
  `recorded_balls` と `complete_probe_balls` が異なる場合は不足分を先に確認する。
- バウンド／フェンス境界以後に実際の `DirectFly` がある球。改修後は0件を期待する。
  SQLはイベント時刻が有効範囲内にある通常の生成データを前提にする。

空中探索を実行した野手で `risk_ok_samples = 0` なのに同じ0.01秒診断が成立する差は、
改修後は原則0を期待する。フィルタ除外後の診断成立は今回の修正対象外なので残り得る。
エラー抽選で失敗した空中捕球は通常の `risk_ok_samples = 1` となり、この差には含まれない。
0.05秒診断と0.01秒診断の差自体は、比較用の粗い診断を残すため今後も存在し得る。
前回の `normal_failed_but_probe_possible` を条件にした比較SQLは、修正後には対象がほぼ消える見込み。

件数が違う場合は割合も比較する。同じシードでも捕球結果が変わると後続の乱数列と試合展開が
変わるため、異なる試合IDを同じ1球の対応比較として扱わない。
今回の環境では利用者の試合DBとRust実行環境がないため、実際の前後集計は新しい試合生成後に行う。
