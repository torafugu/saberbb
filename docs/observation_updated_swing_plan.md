# 確定前の観測履歴による到達予測の更新

## 今回の比較

先行する予測診断では、確定時点の球位置だけを正確に観測し、速度・加速度には独立な
`expected_ball`をそのまま使っていた。今回は同じ球の過去3時点の位置から速度・加速度を
推定し直し、位置・到達時刻の誤差と接触品質を比較する。
本体の見送り判断・接触採否・打球結果・乱数消費は変更しない。

| 条件 | 推定に使う情報 |
|---|---|
| prior_only | 従来どおり、確定時点の正確な位置＋expected_ballの速度・加速度 |
| observed_sigma_0.002 / 0.005 / 0.01 | 確定以前の3観測へ位置誤差を加え、速度・加速度を更新 |
| exact_observation_control | 正確な3観測から推定する誤差なし対照 |

誤差なし対照は、一定加速度モデルについて到達予測の上限を確認するためのもの。
接触率100%の保証ではない。実行角度誤差、有限な接触区間、探索範囲などは残る。
従来条件にも正確な確定時位置を与えるため、センサー条件が完全に対称な比較ではない。
新条件では位置の観測誤差も計画へ伝わる。

## 保存と因果的な境界

`SwingPredictionInput.observation_history`を任意の配列として追加する。
時刻は予測事前モデルの飛行時間の0.2、0.4、0.6倍。最後が従来の確定時刻。
位置は既存の実球の一定加速度軌道を収集側でサンプリングする。
履歴の全時点が確定以前であり、確定が実球到達以前であることを確認する。
予測器へ実際の到達位置・到達時間・接触結果は渡さない。
過去の観測位置を作る収集側と、その観測だけを読む推定器を分ける。
JSON本体・予測オブジェクトのversion/source、テーブル定義は従来のまま。
追加フィールドはserde(default)で旧JSONを読める。DB移行は不要。

**改修後のコードで新しい試合を生成する必要がある。24535～24894には履歴がない。**
旧試合は保持し、履歴なしは`missing_observation_history`として集計する。
実球の最終状態から古い行の履歴を補完しない。

## 推定と観測誤差の仮定

3観測を(t0,p0),(t1,p1),(t2,p2)とし、X/Zは次で推定する。

```text
a = 2 * ((p2-p1)/(t2-t1) - (p1-p0)/(t1-t0)) / (t2-t0)
v_at_t2 = (p2-p1)/(t2-t1) + 0.5*a*(t2-t1)
```

現行シミュレーターのY加速度は0なので、Yは`(p2.y-p0.y)/(t2-t0)`で速度を推定し、
加速度は0にする。更新は3観測による置換であり、事前値との重み付き混合ではない。
既存の`forecast()`へ最後の観測と推定速度・加速度を渡す。

センサー誤差は各時点・各軸の独立な標準正規値に次の幅を乗じる。

```text
sigma_effective_m = sigma_base_m * exp(-0.5 * clamp(batting_eye, -4, 4))
```

基準幅は2/5/10mm。**幅・能力係数とも未校正の感度分析用の仮定**であり、人間の視覚や
実際のContact率に合わせた値ではない。時刻の観測誤差は入れない。
位置の微小誤差も差分による速度・加速度推定では増幅するので、幅別に結果を見る。

標準正規値はgame_id/count_seqと固定文字列のSHA-256からローカルなRandomを作り生成する。
本体のRNGやPythonのグローバル乱数状態は使わない。全幅・能力条件で同じ標準正規値を共有する。
入力JSONLへ実際に使った観測と推定ベクトルも出力する。

`batting_eye`は観測誤差幅、`bat_control`は保存済みの実行角度誤差に対応する。
今回の比較では**実行角度誤差を従来予測条件の値に固定**する。
新しい予測高さから予定バット角を計算するが、新コースのzone_modifierを再現したと主張しない。
打者のゾーン特性全体は保存されていないためで、将来の本体適用時には再検討する。
攻撃角・バット速度・支点モデル・衝突係数・探索±60msは共通。
新予測の時刻だけを位相へ適用し、旧timing_offsetを足さない。

## 実行

main取り込み・ビルド後に試合を追加生成し、新規試合ID範囲を指定する。

```sh
python3 tools/diagnostics/observation_update_probe.py --db "/path/to/saberbb.db" --first-game-id 25000 --last-game-id 25359 --output-dir ../saberbb_observation_update
```

IDは実データへ置換する。出力先は未作成のディレクトリ。
既定は5条件×L=0.6/0.9/1.2mで1球15試行。
`--sensor-sigma-m 0 0.002 0.005`などで幅を指定できる。
DBはmode=ro/query_onlyの読み取りトランザクションで開く。

## 出力と評価順

1. `observation_update_coverage.csv`と`status.csv`：全スイング、有効履歴、欠損・不正履歴、試行件数。
2. `observation_update_error_summary.csv`：条件・能力帯別のX/Z/時刻誤差の符号平均・絶対平均・p50/p90/p99。
3. `observation_update_eye_summary.csv`：同一球・同一標準誤差でeyeだけを-2/0/+2に変更した感度。
4. `observation_update_summary.csv`：接触・非接触・未収束、EV/VLA/ファウル方向率など。
5. `observation_update_transitions.csv`と`pairs.csv`：従来予測から各条件への同一球の状態遷移、双方接触した球の品質差。

実能力帯の比較は球集合が違うため、能力効果の切り分けにはeyeの反実仮想比較を使う。
eyeによる誤差減少はこの式で与えた性質であり、現実への妥当性を確認した証拠ではない。
誤差なし条件のX/Z/時刻残差が数値丸め程度かをまず確認する。

`observation_update_forecasts.csv`は1球×条件、`eye_sensitivity.csv`は1球×幅×能力の明細。
`contacts.csv`は全接触探索、`inputs.jsonl`は計画と観測、`metadata.json`は全仮定。
`contact_3d_status.csv`/`quality.csv`も出力する。
summaryの平均は条件ごとの接触集合、pairsは同一球の双方接触集合。
all行と帯域別行を合算しない。ファウル方向は最終試合結果ではない。
推定失敗は全条件比較の分母から除外してstatusに理由を残す。
ゲームIDが変わると誤差サンプルも変わるため、同一球比較には同じDBを使う。

まず予測誤差と能力感度を評価し、その後に接触結果を見る。
接触率に合わせてセンサー幅や反発係数を調整したり、この段階で本体へ適用したりしない。

## 検証

Python診断・SQLテストで解析解、因果的な入力境界、共通誤差、能力幅、欠損の分母、
誤差ゼロ条件の同一性、DB不変性、旧JSON相当の欠損を検証する。
Rustには観測時刻・軌道位置・任意フィールドの往復と旧JSON互換テストを追加。

```sh
python3 -m unittest discover -s tests/diagnostics -p 'test_*.py'
python3 -m unittest discover -s tests/sql -p 'test_*.py'
cargo test swing_prediction
```
