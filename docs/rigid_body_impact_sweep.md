# 並進・角速度を保つ軸方向打点掃引

実接触の速度/打点集計では、遅い接触は手元側に偏り、先端側+0.08m以上の最低点速度は約33.06m/sだった。旧掃引では点速度を打点ごとに固定していたため、この結びつきがなかった。比較用に `impact_parameter_sweep.py` に剛体運動モードを追加する。

```sh
python3 tools/diagnostics/impact_parameter_sweep.py \
  --output-dir ../saberbb_rigid_impact_sweep \
  --velocity-model both \
  --axials-m -0.12 -0.08 -0.04 0 0.04 0.08 0.10 0.12 0.13
```

DB・入力CSV・接触探索は不要。既定の投球38m/s、基準点速度35m/s、速度角5度、軸傾き-45/-30/0/30/45度、b/Rの2001点を用いる。上の指定では2運動モード×5姿勢×9打点×2001点×3応答モデル=540,270行。出力先の上書きは拒否する。

## 速度の定義

基準点は軸方向座標s=0。`--bat-speed-ms` と `--attack-deg` で、その世界速度V0を定める。軸a・レバー長Lから角速度 `omega = cross(a,V0)/L` を作る。

- `fixed_point`（従来の既定値）: 各打点の点速度をV0に固定。打点を移すたびに、ソルバーが導く重心速度・支点並進速度も変わる。
- `rigid_body`: `V(s) = V0 + cross(omega,a*s)` とする。同じ姿勢の軸方向掃引中に、角速度・重心速度・支点並進速度を保持する。
- `both`: 両方を同じb/Rグリッドで実行する。全出力の `velocity_model` 列で識別する。

バット重心の軸方向座標をcとすると、ソルバーへ渡す点速度から `Vcm=V(s)-cross(omega,a*(s-c))` を求める。rigid_bodyではsに依存しないことを検査する。支点速度 `Vp=V(s)-cross(omega,a*(L+s))` についても同じ検査を行う。

軸水平・V0=(0,35,0)m/s・L=0.9mなら、先端側+0.10mの速度は38.889m/s、手元側-0.10mでは31.111m/sになる。軸方向並進成分がある場合もベクトル式を使い、単純な速度比で代用しない。

各sで法線の接近基底も新しい点速度から計算し直す。b/Rの定義、質量・慣性・反発曲線・回転数・応答モデルは元の掃引と同じ。位置別反発係数はsに応じて変わる。全モデル/姿勢を横断して同じ重心速度という意味ではなく、**同じ姿勢のrigid_body掃引の軸方向ケース間**で固定する。

## 出力の追加・変更

既存のsamples/summary/minima/weak_fair_intervalsに `velocity_model` 列を追加。samples/minimaには実際の `bat_point_speed_ms` も記録する。モードが重なるため、モデル・運動モードを混ぜて合算しない。

`impact_sweep_kinematics.csv` はb/Rと応答モデルに重複させない、運動モード×姿勢×軸方向打点の一覧。点速度、重心速度、支点速度はm/s、omegaはrad/s。各ベクトルのx/y/z列を出力する。

checksの `rigid_cm_velocity_ms`、`rigid_pivot_velocity_ms` は基準点s=0での値との差、`rigid_point_velocity_ms` は支点から計算した速度との一致誤差。幾何・応答保存則・normal_profile/finite_mu0対照も従来どおり検証する。

metadataはversion=2。従来のbat_point_speed_msという入力名はreference_point_speed_msに改め、基準点速度と実際の接触点速度の違いを明確にする。CLIでモードを指定しなければ従来のfixed_point計算を維持するが、CSVの列とmetadataの形式は更新する。

## 初回結果

上のコマンドを実行し、主モデル `finite_I0.00015_et0.4` のグリッド上の最低フェア方向EVを比較した。

| 軸傾き | 軸方向打点 | 点速度固定 | 剛体運動 |
| --- | --- | --- | --- |
| 0度 | +0.10m | 25.900m/s | 27.868m/s |
| 0度 | +0.12m | 23.249m/s | 25.755m/s |
| 0度 | +0.13m | 22.253m/s | 24.918m/s |
| 30度 | +0.10m | 26.087m/s | 28.237m/s |
| 30度 | +0.12m | 23.388m/s | 25.950m/s |
| 30度 | +0.13m | 22.372m/s | 25.107m/s |
| 45度 | +0.13m | 22.868m/s | 25.370m/s |

基準点速度35m/sでは、先端側の速度増加が低EV領域を狭める。たとえば水平軸・s=+0.13mの弱いフェア方向グリッド点は1005点→61点、30度軸では892点→0点。点数は実際の発生確率ではない。

この設定は実データの各投球を再現したものではない。実データは投球速度・基準速度・姿勢・回転に幅があり、弱い打球を生成できないという一般的な証明にはならない。最小値と区間はグリッド近似で、実際にその衝突が軌道上で起きるかも判定しない。係数やゲーム結果は変更しない。

既定と同じ条件の結果はローカルでも再現できるため共有不要。条件を変更した場合は実行コマンドとsummary、kinematics、weak_fair_intervals、checksを共有して比較する。
